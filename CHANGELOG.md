# Changelog

All notable changes to Codeveira are documented here.

## [Unreleased]

### Security

- **`app` and `lsp` no longer publish their ports directly to the host — only the bundled `nginx` container does.** Previously `app:3000` and `lsp:7777` were published to the host *in addition to* nginx's `443`/`80`, so anyone could reach either one directly in plain HTTP/TCP, bypassing nginx and TLS entirely regardless of Domain & HTTPS configuration — `FORCE_SSL=true` didn't fully close this, since the first request (session cookie, login password) still traveled in cleartext before any redirect could fire. **Action required if you run your own external reverse proxy instead of the bundled nginx** ("Bring your own reverse proxy" in the README): merge the new `docker-compose.byo-proxy.yml` (`docker compose -f docker-compose.yml -f docker-compose.byo-proxy.yml up -d`) to republish those two ports, and comment out the bundled nginx's own `ports:` block by hand (Compose can't subtract it via an override). Everyone using the bundled nginx (the default, recommended setup) needs no action — `docker compose up -d` already only publishes 80/443/7777 from nginx now.
- **Repository access control (IDOR) fix** — `Browse`, `Reviews`, `Comments` (including posting new comments), `Labels`, `Commits`, and the repository overview/README/metrics/analytics pages now correctly scope repository lookups to repos the current user is a member of (or all repos for global admins). Previously any logged-in user could view — and in some cases modify — data belonging to a repository they weren't a member of, just by changing the numeric `repository_id` in the URL. The REST API and MCP server were already scoped correctly and are unaffected.
- **Azure DevOps and Gerrit webhooks now require authentication.** These platforms don't support HMAC payload signing the way GitLab/GitHub/Gitea/Bitbucket do, so requests are now authenticated via HTTP Basic Auth instead — set `AZURE_WEBHOOK_SECRET`/`GERRIT_WEBHOOK_SECRET` and configure the matching password on the webhook subscription/plugin config. **Action required on upgrade:** these webhooks will start rejecting requests with `401` until the new env vars are set and the receiving side is configured to send Basic Auth.
- **Encryption at rest for Repository access tokens, AI provider API keys, user API tokens, and sensitive settings** (CI webhook token, SMS API token, etc.) via Rails Active Record Encryption. **Action required on upgrade:** set `ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY`, `ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY`, and `ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT` in `.env` before starting — the app won't boot without them. Existing values are re-encrypted automatically the next time `rails db:migrate` runs; nothing is lost or requires manual re-entry.
- **SSRF protection** for the repository instance URL (self-hosted GitLab/Gitea/Forgejo/Bitbucket Server/Azure DevOps/Gerrit), outgoing webhook URLs, and the AI reviewer's custom API URL — blocks cloud metadata endpoints and the app's own internal service names, while still allowing arbitrary internal hostnames and private IP ranges (required for these self-hosted/internal-network features to keep working).
- **Account lockout** — 10 failed login attempts locks an account for 1 hour, closing off online brute-force against `/users/sign_in`. Minimum password length raised from 6 to 8 characters.
- **`FORCE_SSL` option** — set `FORCE_SSL=true` once TLS is terminated in front of the app to redirect HTTP→HTTPS and mark session cookies `Secure`.
- **Backup upload hardening** — uploaded `.dump` files are now checked against a maximum size (`MAX_BACKUP_UPLOAD_SIZE`, default 2GB) and a valid pg_dump custom-format signature before being accepted for restore.
- **Non-root containers** — `app`, `sidekiq`, `indexer`, and `lsp` now run their application process as a non-root user rather than root, reducing the impact of any future RCE in a dependency.
- **Upsource import SSRF check now enforced per-request**, not just once when the URL is first entered — closes a DNS-rebinding window during the (potentially long-running, re-runnable) import job.

### Added
- **Real semantic analysis, Phase 1: Go/gopls** (Enterprise) — opt-in per repository (**Edit page → "Enable real semantic analysis (Go)"**, same toggle pattern as the outgoing-webhooks override), a new subsystem alongside (not a replacement for) the existing tree-sitter symbol indexer: drives the real `gopls` language server against the repository's Go module, so its diagnostics are actual `go vet`/compiler output and its definitions are type-resolved rather than name-matched. Triggers automatically on every push via a new `semantic-analysis` container (`POST /analyze`, shared-secret auth), guarded by a coalescing check that skips (rather than queues) a new run if one is already in progress for that repository/branch. Rails is the only thing that ever talks to your git host — it fetches the repository archive itself (GitLab only, for now) and streams it to the container over the internal Docker network; the container never talks to your git host at all. Because this is the first Codeveira feature to run a target repository's own dependency-install tooling (`go mod download`), it ships with a real egress allow-list from day one: a new `semantic-analysis-proxy` container restricts the analysis container's only route to the internet to `proxy.golang.org`/`sum.golang.org`/`storage.googleapis.com`, the Go module proxy's own domain set. New review-page "Semantic Analysis" panel shows run status, definition/diagnostic counts, a staleness warning if the run's commit doesn't match the review's current HEAD, and a diagnostics list linking into the diff at each finding's file. New `SEMANTIC_ANALYSIS_TOKEN`/`SEMANTIC_ANALYSIS_MEM_LIMIT`/`SEMANTIC_ANALYSIS_CPUS` env vars. Not yet built: other languages (TypeScript, Java, Kotlin, Python, PHP, C#, Ruby), a typed Find-Usages/Go-to-Definition upgrade, diagnostics inlined into diff hunks, non-GitLab archive fetching
- **Real semantic analysis, Phase 2: TypeScript** (Enterprise) — a second opt-in language on the same subsystem Phase 1 shipped, not a rebuild of it: a new `semantic_analysis_language` column on `Repository` (`go`/`typescript`, default `go`) drives a **Language** dropdown next to the existing "Enable real semantic analysis" toggle on the repository Edit page (the toggle's own label dropped the "(Go)" suffix now that it covers both). Drives `typescript-language-server` as an LSP subprocess exactly like Phase 1 drives `gopls` — `.ts`/`.tsx` files, plus `.js`/`.jsx` alongside them, requires a `tsconfig.json` at the workspace root to run at all, and conditionally runs `npm ci --ignore-scripts` (not full `npm install`) when a `package.json` is present. New `semantic-analysis-ts` container (its own Dockerfile, port `8093` alongside Go's `8092`) and its own dedicated egress-allowlist proxy, `semantic-analysis-ts-proxy` (tinyproxy, scoped to `registry.npmjs.org` only) on its own internal-only Docker network (`semantic_analysis_ts_net`) — fully separate from Go's `semantic-analysis-proxy`/`semantic_analysis_net`, not shared, so each sandboxed language keeps its own toolchain and its own dependency-execution trust boundary. New `SEMANTIC_ANALYSIS_TS_URL`/`SEMANTIC_ANALYSIS_TS_TOKEN`/`SEMANTIC_ANALYSIS_TS_MEM_LIMIT`/`SEMANTIC_ANALYSIS_TS_CPUS` env vars, following the exact same pattern as the existing Go vars, which are unchanged. The review-page "Semantic Analysis" panel, the `semantic_analysis_runs`/`semantic_definitions`/`semantic_diagnostics` tables, and the persistence path are all shared and language-agnostic — no per-language table split. Not yet built: other languages (Java, Kotlin, Python, PHP, C#, Ruby), a typed Find-Usages/Go-to-Definition upgrade (still tree-sitter-based navigation for both languages), diagnostics inlined into diff hunks (still a standalone review-page panel), dependency-install caching (every run does a fresh `npm ci`/`go mod download`), yarn/pnpm lockfile support (npm/`package-lock.json` only)
- **Hotspots analytics tab** (Free) — new **Hotspots** tab on repository Analytics ranks files by churn × usage (commit frequency from existing file-ownership stats, multiplied by symbol-reference count on the default branch from the existing symbol index); a file with only one signal — churned but never referenced, or referenced but never changed — scores zero and is excluded, so generated/vendored files and untouched-but-linked stable code don't crowd out real hotspots; bar chart (top 15) plus full table (top 30)
- **Technical debt analytics tab** (Free) — new **Tech Debt** tab on repository Analytics: open lint-violation and duplicate-code counts, a trend chart of both over the selected range, and a code-coverage-% trend line — all aggregated from data Architectural Lint, Duplicate Code Detection, and Code Coverage already produce, no new tracking table or scan

Both Sidekiq and ActionCable's Redis clients are Sentinel-aware — they auto-discover the current master via `REDIS_SENTINELS`/`REDIS_MASTER_NAME` and reconnect after a failover with no restart needed. See [Redis Sentinel](README.md#redis-sentinel-optional) in the README.

### Fixed
- **Semantic Analysis (Go/TypeScript/Python) was undeployable from this compose file** — `semantic-analysis`, `semantic-analysis-ts`, and `semantic-analysis-py` (plus their three dedicated egress-allowlist proxies) were documented in this README/CHANGELOG/`.env.example` but never actually wired into `docker-compose.yml`, so enabling the feature on a repository would just fail with unreachable sidecar errors — the deploy compose file simply had no service blocks for any of the three languages, even though the main source repo's own `docker-compose.yml` (build-from-source) has had them since each language shipped. Added all six service blocks (`image: ghcr.io/codeveira/codeveira-semantic-analysis[-ts|-py][-proxy]`), their three `internal: true` networks, and the matching `SEMANTIC_ANALYSIS[_TS|_PY]_URL`/`_TOKEN` env vars + `depends_on` entries on `sidekiq`. The CI workflow (`.github/workflows/docker.yml`) is also updated to actually build and push those six images to `ghcr.io` — they didn't exist there before either, which is why this went unnoticed.
- **Encrypted settings could silently return raw ciphertext instead of failing loudly** — if a stored value couldn't be decrypted under the currently configured `ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY` (most plausibly: a database backup restored into an environment with a different encryption key than the one it was created under), `AppSetting.get` used to hand back the raw encrypted blob as if it were the plaintext value, thanks to Rails' `support_unencrypted_data` compatibility setting silently swallowing the decryption error. Now detects Active Record Encryption's own envelope shape on the returned value and treats it as unset (with an error logged naming the affected setting) instead of leaking ciphertext into any page, webhook payload, or log line that reads it — affects all 100+ call sites across the app, not just the one (Checklist Enforcement's repository Edit page) it was first spotted on.
- **Settings forms silently discarding their success/error message in the browser** — a layout-wide `<meta name="turbo-visit-control" content="reload">` tag (added for an unrelated reason) caused Turbo Drive to silently drop the flash message on nearly every Settings form submission — both validation errors and successful saves — making a save look like it did nothing, or like a choice had silently reverted. Fixed across every affected Settings page (Domain & HTTPS, License, AI Prompts, Review Templates, Access Control, Audit Log, Checklist Enforcement, Architectural Lint, Notifications, Users, Backup & Restore, Upsource Import, CI Integration, Webhook Deliveries).
- **Backup schedule always active** — scheduled database backup (`database_backup` Sidekiq Cron job) is now registered at Sidekiq startup even when the user has never explicitly clicked **Save schedule**; default schedule is daily at 3:00 AM UTC
- **Backup upload** (Standard) — **Upload Backup** section added to Settings → Backup & Restore; drag & drop or file picker to upload a `.dump` file from your computer; uploaded file appears in the Saved Backups list immediately and can be restored like any other snapshot; nginx `client_max_body_size` raised from 10 MB to 512 MB to accommodate large dump files
- **Backup & Restore progress UI** (Standard) — real-time feedback for backup and restore operations: clicking **Backup now** shows a live spinner banner; on completion the banner turns green with the backup filename and the page auto-reloads; clicking **Restore** shows a full-screen blocking overlay with a spinner; when the restore finishes the overlay transitions to a green confirmation with an **OK** button that reloads the page; works correctly even after restore invalidates the user session

### Performance
- **Diff stats pre-computed** — `additions_count` / `deletions_count` columns added to `commits` table; stats are computed once on save and read from DB instead of being parsed from raw diff text on every request; dashboard and review list performance improved significantly for large repositories

### Changed
- **Upsource import wizard** moved from Standard to **Enterprise** tier

### Changed
- **Licensing model** — removed user limits from all tiers; every tier (including Free) now supports unlimited users. License key records the number of paid seats (`paid_users`) for billing reference only — no enforcement in the application
- Pricing changed to flat per-user rates: Standard $10/user/mo, Extended $14/user/mo, Enterprise $16/user/mo
- `bin/generate_license` flag renamed from `--max-users` to `--paid-users`
- License validation now rejects keys missing the `paid_users` field (old keys with `max_users` are rejected — regenerate using the new `--paid-users` flag)
